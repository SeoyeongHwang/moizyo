## 1. 프로젝트 개요
---
### 한 줄 정의
타임테이블 히트맵 기반 회의 시간 조율 도구

### 제품 목표
사용자들이 눈치 보지 않고 솔직하게 선호 시간을 입력하도록 유도하여, 모두가 최대한 만족할 수 있는 최적의 회의 시간을 효율적으로 찾고, 회의 시간 조율 과정에서 발생하는 비효율적인 전략적 응답과 의사소통 비용을 최소화합니다.

### 배경
기존 회의 시간 조율 방식은 수동적인 연락, 복잡한 스프레드시트 사용 등으로 인해 많은 시간이 소요되며, 참가자들의 실제 선호도를 정확히 파악하기 어렵다는 문제점이 있습니다. 특히 참가자들이 다른 사람의 응답을 의식해 전략적으로 시간을 입력하는 경향이 있어, 모두에게 최적화된 시간을 도출하기 어렵습니다. 현재 'When2meet'과 같은 도구도 이러한 섬세한 선호도를 다루는 데는 한계가 있습니다. 이에 참가자들의 솔직한 의견을 효과적으로 수집하고 시각적으로 분석하여, 빠르고 만족스러운 회의 시간 조율 경험을 제공하고자 합니다.

### 사용자 문제
회의 시간 조율에 너무 많은 시간이 소요되고, 참가자들의 실제 선호 시간을 파악하기 어려우며, 다른 사람의 눈치를 보거나 전략적으로 시간을 입력하게 되어 최적의 시간 도출이 어렵습니다.

### 해결 방안
히트맵 시각화를 통해 모든 참가자의 가용 시간을 한눈에 파악할 수 있도록 합니다. '가능하지만 비선호' 시간을 포함한 섬세한 시간 입력 UX를 제공하여 솔직한 응답을 유도하고, 응답 시 다른 참가자의 응답을 숨겨 전략적 응답을 방지합니다. 회의 소요 시간에 따른 최적의 시간 후보를 자동으로 추천하고, 필수 참가자를 고려해 제안합니다. 최종 선정된 회의 시간의 근거를 요약하여 공유하는 기능을 제공하여 의사소통 비용을 절감합니다.

### 차별점
'가능하지만 비선호' 시간 입력을 통해 참가자들의 미묘한 선호도까지 파악하고 이를 시각화 및 추천 로직에 반영함으로써, 단순한 '가능/불가능'을 넘어선 더 만족스러운 시간 조율을 가능하게 합니다. 또한, 응답 시 이전 참가자의 응답을 숨김으로써 심리적인 부담을 줄여 솔직하고 정확한 답변을 유도하는 것이 핵심적인 차별점입니다.

### 타겟 사용자
사무실 환경에서 팀 프로젝트 킥오프, 내부 팀 회의 등을 자주 진행하며 6~10명 규모의 회의 시간을 조율하는 데 어려움을 겪는 직장인입니다. 특히, 회의 조율에 많은 시간을 소모하고 참가자들의 솔직한 의견을 반영하여 모두가 만족할 만한 최적의 시간을 찾고자 하는 팀 리더 또는 실무 담당자입니다.

### 사용자 시나리오
팀장이 새로운 프로젝트 킥오프 회의를 위해 8명의 팀원들의 가용 시간을 조율해야 합니다. 그는 기존 방식대로 개별적으로 연락하거나 복잡한 스프레드시트를 만드는 대신, 이 도구에 접속하여 회의 종류('프로젝트 킥오프'), 목적, 날짜, 시간대, 소요 시간(1시간)을 입력하고 투표를 생성합니다. 생성된 링크를 팀 단체 채팅방에 공유하고, 팀원들은 링크에 접속하여 자신의 이름을 입력하고 타임테이블 위에서 드래그 앤 드롭으로 '가장 좋은 시간'과 '가능하지만 비선호하는 시간'을 표시합니다. 이때 다른 팀원들의 응답은 보이지 않습니다. 모든 팀원의 응답이 수집되면, 팀장은 히트맵 형태의 결과 화면에서 전체 가용 시간을 한눈에 확인하고, 1시간 소요 시간에 따른 추천 시간 후보들을 검토합니다. 특히 필수 참석자의 가용성을 고려하여 최적의 시간을 최종 선택합니다. 최종 선정된 시간과 그 근거를 자동으로 생성된 메시지로 팀원들에게 공유하여 효율적으로 회의를 확정합니다.

### 핵심 지표
사용자의 최적 시간 발견 빈도 증가 (예: 추천 시간 수락률 70% 이상), 회의 시간 조율에 소요되는 평균 시간 50% 단축, 불필요한 의사소통 (예: 재조율 요청) 30% 감소, 투표 참여율 80% 이상, 월간 활성 사용자(MAU) 및 재방문율.

### 리스크
초기 사용자 유입 및 온보딩 어려움, 기존 도구 사용 습관으로 인한 전환 저항, 참가자들이 여전히 눈치 보거나 전략적으로 응답할 가능성, 유사 기능 경쟁 서비스의 등장 및 차별성 유지 문제, 동시 접속자 증가 시 기술적 안정성 및 성능 저하 가능성.

## 1. 회의 투표 생성 및 공유
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자가 회의, 모임 등의 이벤트를 생성하고, 이벤트 종류, 목적, 날짜, 시간대, 소요시간 등을 입력하여 투표를 시작할 수 있습니다. 생성된 투표는 공유 가능한 링크 형태로 제공됩니다.

**수용 기준:**
```
1. ○ 사용자는 이벤트 종류, 목적, 조사 날짜, 조사 시간대, 이벤트 소요 시간을 입력하여 투표를 생성할 수 있다.
2. ○ 생성된 투표에 접근할 수 있는 고유한 링크가 자동으로 생성된다.
3. ○ 생성된 링크는 복사하여 메신저 등에 쉽게 공유할 수 있다.
```

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 생성자 | **기기**: Web, Mobile


#### 1.1.3 조사 날짜 선택 필드

사용자가 투표 대상 날짜를 캘린더 또는 날짜 선택 위젯을 통해 지정할 수 있습니다. 단일 날짜 또는 복수 날짜 선택을 지원합니다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 생성자 | **기기**: Web, Mobile


#### 1.1.4 조사 시간대 선택 필드

사용자가 투표에서 조사할 시간대의 시작 시간과 종료 시간을 입력하는 필드를 제공합니다(예: 09:00 ~ 18:00).

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 생성자 | **기기**: Web, Mobile

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 생성자 | **기기**: Web, Mobile

## 2. 참가자 시간 입력 및 선호도 반영
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

참가자는 투표 페이지에 접속하여 자신의 이름을 입력하고, 타임테이블 위에서 '가장 좋은 시간'과 '가능하지만 비선호하는 시간'을 드래그 앤 드롭 방식으로 표시할 수 있습니다. 다른 참가자의 응답은 숨겨져 솔직한 답변을 유도합니다.

**수용 기준:**
```
1. ○ 참가자는 투표 진입 시 이름을 입력해야 한다.
2. ○ 참가자는 타임테이블 위에서 '가장 좋은 시간'을 드래그 앤 드롭으로 표시할 수 있다.
3. ○ 참가자는 '가능하지만 비선호하는 시간'을 별도로 표시할 수 있다.
4. ○ 참가자가 시간을 입력하는 동안 다른 참가자의 응답은 보이지 않아야 한다.
5. ○ 표시되지 않은 시간은 자동으로 '불가능한 시간'으로 처리된다.
```


### 2.1 참가자 이름 입력
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 참가자 | **기기**: Web, Mobile

참가자가 투표 페이지 진입 시 자신의 이름을 입력할 수 있는 입력 필드를 제공합니다.


#### 2.1.1 이름 입력 필드 및 검증

참가자가 투표 페이지 진입 시 이름을 입력할 수 있는 텍스트 필드를 제공하고, 빈 입력을 검증하여 필수 입력 안내를 제시합니다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 참가자 | **기기**: Web, Mobile


#### 2.1.2 이름 중복 처리

같은 투표에서 이미 입력된 이름의 중복을 검사하고, 중복 시 안내 메시지를 표시합니다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 참가자 | **기기**: Web, Mobile


#### 2.1.3 이름 확인 및 진행 버튼

유효한 이름 입력 후 '진행' 또는 '확인' 버튼을 클릭하면 시간 입력 단계로 진행하는 로직을 구현합니다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 참가자 | **기기**: Web, Mobile


### 2.2 타임테이블 드래그 앤 드롭 UI
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 참가자 | **기기**: Web, Mobile

참가자가 타임테이블 위에서 시간 블록을 드래그 앤 드롭으로 조작할 수 있는 인터랙티브 UI를 제공합니다.


#### 2.2.1 타임테이블 기본 UI 렌더링

투표 생성 시 지정된 날짜와 시간대를 기반으로 타임테이블(격자 형태)을 렌더링합니다. 가로축에 시간, 세로축에 참가자를 표시합니다.

**수용 기준:**
```
1. ○ 모든 참가자의 응답이 완료되면 응답 히트맵이 표시된다.
2. ○ 히트맵은 '가능한 시간'과 '가능하지만 비선호 시간'을 모두 '가능한 시간'으로 처리하여 시각화한다.

6. ○ 생성자는 응답자 목록에서 필수 참가자를 지정할 수 있으며, 필수 참가자의 가용성은 추천 시간 후보 선정 시 우선적으로 반영된다.
```

## 4. 선택된 회의 시간 확정 및 공유
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

생성자가 추천 후보 중 최적의 회의 시간을 선택하여 확정하면, 해당 시간 선택의 근거를 요약한 안내 메시지가 자동 생성되어 링크와 함께 메신저 등에 쉽게 공유할 수 있도록 제공됩니다.

**수용 기준:**
```
1. ○ 생성자는 추천 시간 후보 중 하나를 최종 회의 시간으로 선택할 수 있다.
2. ○ 최종 선택된 회의 시간과 그 선택 근거를 요약한 메시지(불렛 형식)가 자동으로 생성된다.
3. ○ 생성된 메시지는 회의 투표 링크와 함께 복사하여 메신저 등에 붙여넣을 수 있다.
```


### 4.1 회의 시간 최종 선택

생성자가 추천 시간 후보 목록에서 최적의 회의 시간 하나를 선택하여 최종 확정할 수 있는 기능을 제공합니다.

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 생성자 | **기기**: Web, Mobile


#### 4.1.2 최종 선택 시간 저장

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 생성자 | **기기**: Web, Mobile
